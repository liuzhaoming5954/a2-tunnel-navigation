# A2-PRO 地下管廊定位导航与巡检方案

**版本 v0.4 · 2026-11-04 · 离线运行设计基线，实机准入指标待分阶段验证**

本版根据方案审阅补充固定路线执行、定位健康、失效停车、任务状态、接口与持久化、原厂交接以及验收规则。**机器人在管廊运行期间没有外部网络，首期必须支持全程离线自主巡检。** 本文中的待确认项是阶段准入条件，未填写、未验证或不通过时，不放行对应自主功能。

## 1. 首期范围与运行约束

| 项目 | v0.4 决策 |
|---|---|
| 运行场景 | 单层、预先建图的地下管廊，从已知入口启动，沿已验收固定路线巡检。正常结束或达到返桩条件后，沿已验收返程路径到原厂充电座并完成对准。 |
| 网络条件 | 运行期间无 Wi-Fi、蜂窝或其他通往上位机/互联网的可靠链路。机内雷达网、SDK/DDS 控制网和载荷连接仍须正常；其故障属于设备故障，不能按“正常离线”忽略。 |
| 运行平台 | A2-PRO 算力背包 NVIDIA Jetson Orin（ARM64），底盘执行宇树原有步态。PC2 仅在必要时转发传感器数据或桥接控制；一旦使用，纳入机载依赖和失效监测。 |
| 传感器 | 原装前后禾赛 JT128、原装前置光学相机及补光灯、上装云台相机和气体传感器。优先验证前雷达内置 IMU；不可用时验证机身 IMU 的时间、外参和频率，未通过则阻止里程计准入。 |
| 软件栈 | ROS 2、禾赛 ROS 驱动、DLIO、RTAB-Map、Nav2 Controller Server / Regulated Pure Pursuit、Collision Monitor、`apriltag_ros`、Unitree SDK2，以及自研路线执行器、任务管理器、健康监控、运动仲裁、载荷适配和网关。 |
| 巡检行为 | 按沿路线拍摄窗口给固定设备拍照，必要时在允许停车点补拍；沿线采集气体并关联位姿。障碍触发减速或停车，持续堵塞按本地预算处理。告警先本地记录和提示，联网后补传。 |
| 上位机 | 用于出发前配置、任务装载和授权，返程或维护联网后的结果同步与查看。有可靠连接且获得独立遥控授权时可用于维护遥控；离线巡检无实时 Web 遥控、实时状态或远程告警送达保证。 |
| 交付终点 | 本项目负责桩前定位和对准，原厂负责接管后的动作、充电启动、充电状态与离桩。对准结果和接管确认分别记录，不能用“已对准”推断“已充电”。 |
| 范围边界 | 首期不自动绕行，不跨层或自主上下楼梯，不自动离桩开启下一任务。FAST-LIVO2 等融合方案留待后续评估。 |

出发前，地图、路线、往返路径、设备点、标签、标定、桩配置、气体规则、故障策略及软件依赖全部位于机载端。离线执行不依赖后端心跳、云端计算、外部鉴权续租、DNS、外部 NTP 或在线许可证校验。路线包中须登记允许的通道宽度、净高、地面/坡度条件、载荷外廓、转向区、禁行区和现场回收方式；现场超出已验收条件时禁止放行。

**离线发生不可恢复故障时，不能以等待 Web 指令作为完成闭环的必要步骤。** 机器人按已装载策略停车、锁存故障并保存记录；人员按出发前登记的预计返回时间、最迟返回时间和失联回收流程处置。超过最迟返回时间仅表示任务超时待核查，不代表平台已实时检测到机器人故障。现场声光提示和独立急停的硬件、触达方式与覆盖范围在 M0 核实。

## 2. 架构、数据流与固定路线

### 2.1 数据流和责任模块

| 输入 | 处理 | 输出或用途 |
|---|---|---|
| 前 JT128 原始点云、已校验 IMU | 禾赛驱动 → DLIO | 连续六自由度里程计；由位姿/TF 适配节点统一转换为机身定义，供全局定位和控制使用。 |
| DLIO 去畸变后的单帧点云、同时间基准的里程计、合格地标观测 | 点云适配 → RTAB-Map | 建图数据库和二维导航栅格；巡检加载已验收数据库，仅做定位并提供 `map → odom`。 |
| 前后原始点云 | 按时间变换、裁剪、滤除机身与地面，按用途降采样 | 局部代价地图和 Collision Monitor。防撞输入直接走低时延支路，不依赖 RTAB-Map 或地图写入；保留经实测可发现低矮障碍的密度。 |
| 前置图像与相机参数 | 去畸变/校正 → `apriltag_ros` → 地标质量校验 | 标签 ID、相对位姿、观测时间、质量及拒绝原因。 |
| 已验收参考路径、路线段、拍摄窗口 | 任务管理器 → 路线执行器 → Nav2 `FollowPath` / RPP | 固定路线跟踪、沿路线进度和异步抓拍调度。 |
| 路线跟踪、维护遥控、桩前对准的速度请求 | 运动仲裁 → Collision Monitor → 底盘桥接 → SDK2 | 唯一自研底盘输出链路；桥接校验授权、限速及新鲜度，调用 `Move()` / `StopMove()`。 |
| 里程计、定位匹配、TF、传感器、底盘和进程状态 | 机载健康监控与定位健康节点 | 统一健康状态、故障原因、运动准入/撤销条件；不依赖网关在线。 |

RTAB-Map 的三维点云输入必须已完成扫描内运动补偿。点云适配接口固定为“**单帧、已去畸变、统一参考时刻、明确 `frame_id`**”；不得误接累计地图或直接把原始扫描与里程计并列输入后认为已去畸变。若所选 DLIO 版本输出位于 `odom` 的点云，适配节点按该帧参考时刻变换到约定扫描坐标系后再送入 RTAB-Map，记录该约定并用录包验证无二次变换。最终字段及输出行为以锁定源码版本为准。

### 2.2 坐标、时间与接口约定

- 连续位姿保存完整三维运动；二维导航使用机身地面投影坐标系 `base_footprint`。TF 链采用 `map → odom → base_footprint → base_link → 传感器`：RTAB-Map 仅发布 `map → odom`，位姿/TF 适配节点从 DLIO 位姿发布后两段动态变换。关闭 DLIO 与其他节点重复的动态/静态 TF 发布；标定发布器是传感器固定外参的唯一发布方。M1 验证组合后的机身位姿与原始里程计一致。
- 坐标采用米、弧度和右手系，机身 x 向前、y 向左、z 向上；光学坐标遵循所选相机接口约定并显式给出外参。用整机资料初始化前后雷达外参，再用重叠点云和实测轴向校验。前雷达 IMU 更换为机身 IMU 时必须重新校验时间与外参，禁止仅换话题名。
- 点云为 `sensor_msgs/PointCloud2`，IMU 为 `sensor_msgs/Imu`，连续位姿为 `nav_msgs/Odometry`。M0 固化话题名、消息字段、频率、QoS、点内时间字段/单位、扫描参考时刻、IMU 重力与轴向约定，以及适配后的 `frame_id`。运动话题按锁定 ROS/Nav2 版本统一消息类型；无头消息由桥接在本地记录接收时间，不作为可跨会话缓存的命令。
- Orin 为机载数据统一时间基准。雷达、IMU、相机、PC2 和载荷分别登记原始时钟域、与机载时间的映射、误差和校验方法；所需同步可使用机内时钟服务或硬件时间，不依赖外部网络。时间偏差超预算时判定相应数据不可用。源端无可靠时间戳的相机不能按网络接收时间冒充曝光时间，应停稳采集并标注时间不确定度。
- 指令超时、租约、等待与重试预算使用机载单调时钟。记录同时包含 `boot_id`、单调时间、原始采集时间及可用的 UTC 时间与可信标记；开机无可靠 UTC 时仍能运行已授权任务，记录相对时间。联网校时不得改变运行中的超时判断，跨重启不能直接比较单调时间或恢复旧租约。
- RTAB-Map 数据库、二维栅格、标签表和路线共享 `map_version`。建图遥控覆盖往返、岔口、设备和桩前；巡检模式禁止在线改写已发布地图。地图定位校正必须受健康监控约束，不允许在全局位姿跳变后直接以新进度触发拍摄。

### 2.3 固定路线执行

首期采用**离线制作并验收参考路径，运行时由路线执行器提交 `FollowPath`**。RPP 负责跟踪；Waypoint Follower 不作为约束固定路线的机制，也不启用运行时自由全局重规划。路径可在建图/维护阶段由工具辅助生成，但必须经过检查、示教复测并随任务包发布。

路线由有向段组成，包含 `segment_id`、行驶方向、参考路径、允许偏离走廊、速度上限、停车/转向位置、拍摄窗口、下一段和已验收返桩连接。相邻段须连续；返程不是仅倒置路径点，需明确机身朝向、允许的倒行或转向动作和防撞覆盖。首期默认前向行驶，特殊倒行只在已单独验收的段/桩前动作开放。

- 路线执行器仅拼接任务中授权的段，维护 `segment_id + direction + 沿线弧长`，以此调度拍摄。路径投影需结合当前段及进度连续性，不允许按全图最近点在相邻支路或往返重叠处跳段。
- 局部障碍导致等待或失败，不能跳过巡检段或搜索其他支路绕行。关闭未经许可的自动旋转、倒退、清空代价地图和重新规划恢复行为；碰撞监控解除不等于任务自动恢复。
- 路线偏离超限、路径失效、不可解释的进度回退或定位跳变时先停车；仅在已验收恢复条件内重新提交路径。禁止为了追赶窗口自动倒车或掉头补拍。
- 每个可达进度点必须有经过验证的返桩方案，包含必要转向空间、合法返程方向和能耗预算。无法覆盖的段不得作为离线自主路线发布。路被持续阻断时按本地等待与回收策略处理，不承诺绕行返回。
- 沟槽、落差、楼梯及不可通行区域纳入禁行地图和现场准入检查；首期不承诺仅靠裁剪后的二维障碍点云识别新出现的坑洞。停车区根据实际步态、载荷外廓和检测到停稳的距离设置。

## 3. AprilTag 辅助定位

目的为缩短长直重复区段的无校验里程，降低纵向漂移导致的错站。标签具有唯一 ID，登记位置、朝向、实际检测边长、服务方向与地图版本；可同时印业务二维码供人工使用。

- 在入口、代表性长直段和易混淆设备前试点，使用哑光标牌。验证补光、行走模糊、距离和往返可见性；必要时同处设置朝向不同且 ID 不同的标签。
- 标定原装广角相机内参、畸变和机身外参。按图像采集时刻匹配机器人位姿，依据距离、角度、连续观测一致性和重投影误差过滤；相机时间或动态识别未通过时，仅开放停稳观测。
- 标签在建图时进入 RTAB-Map 数据库，巡检使用该版本的地标。锁定版本若支持当前 AprilTag 消息则直接接入，否则实现显式适配；不得以“后续兼容”替代 M1 接口验证。DLIO 保持连续里程计，地标只参与全局校正。
- 标签尺寸、间距、允许无校验距离和校正幅度按到点需求与样本试验确定。在相同路线比较有无地标的误差，测试遮挡、漏读、错误 ID 与往返场景。临近无校验距离上限时，按配置减速或停稳复读；超过上限且不能确认位置时停止自主运动。
- 需要对应图纸里程时，另外建立标签与测量坐标的关系。单纯使用 SLAM 中的标签坐标不能替代独立的验收测量基准。

## 5. 任务状态、运动授权与返桩交接

### 5.1 离线运行约束与本地决策

- 本期机器人在巡检运行中**没有可用外部网络**。任务、地图、路线、设备点、阈值、原厂交接方式和异常处置策略必须在出发前下载、校验并冻结；途中不得依赖 Web 后端作出运行决策。
- “无外部网络”不包括机内通信：雷达、相机、载荷和 Unitree SDK/DDS 所需的机内链路必须正常。机内链路失效按对应传感器或控制故障处理。
- 已授权的自主任务在外网缺失期间继续执行；外网状态只影响同步状态，不直接触发自主任务暂停、返桩或恢复。
- 人工遥控必须使用已验证的现场通信链路和独立控制会话。仅当前运动来源为 `TELEOP` 且会话绑定当前 `control_epoch` 时，遥控链路丢失、松开使能、会话到期或命令过期才撤销该授权并停车，且不自动切回自主任务。已撤销或非当前会话失效只使其命令无效，不撤销正在执行的自主授权。
- 所有运行异常先在机载侧处置并持久化。使用已验证的本机或现场指示方式提示；没有实时上报成功的证据时，不能将事件标记为“已通知操作员”。
- 出发前登记任务预计完成时间、最晚返回时间、人工检查时间和回收方式。机器人异常停留或超过返回时限后的检查与回收，由该预案触发，不依赖机器人在线求助。

### 5.2 任务状态机与恢复条件

任务状态和运动授权分别维护。同一机器人只允许运行一个活动任务；准备新任务包不改变当前任务。任务管理器是任务状态的唯一写入者，运动仲裁器是自研运动授权的唯一写入者。任务管理、运动控制或关键健康模块重启时，依赖该模块的运动授权立即失效，恢复时先进入无授权状态；网关或同步进程重启本身不撤销机载自主授权，当前遥控会话失效仍按遥控规则处理。

| 任务状态 | 进入与退出条件 |
|---|---|
| `READY` | 离线任务包已校验，尚未允许运动；收到有效现场启动授权后进入自检。 |
| `PRECHECK` | 检查地图与路线版本、机内通信、载荷、存储、电量、停车机制及原厂控制权；通过后进入定位，否则锁存故障。 |
| `LOCALIZING` | 使用已知入口位姿初始化；定位健康达到启动条件后进入巡检，超时进入故障暂停。 |
| `INSPECTING` | 按冻结路线执行巡检；正常结束或返桩电量触发时进入返桩。 |
| `WAITING_OBSTACLE` | 检测到阻塞先停车；在有限等待预算内持续检查障碍、定位、电量和原任务状态。 |
| `PAUSED_OPERATOR` | 有效暂停或维护接管先停车并保存进度；继续任务须重新确认健康状态并取得当前有效授权。 |
| `RETURNING` | 沿已验收的返程路线驶向桩前；返程阻塞使用单独的等待预算，不能无限等待。 |
| `ALIGNING` | 获得桩前对准授权后执行有限时间、有限次数的闭环对准；成功后按出发前配置进入对准终态或交接等待。 |
| `COMPLETED_ALIGNED` | 仅对准模式下，确认对准、停稳并撤销全部自研运动授权后任务结束；等待约定的原厂流程或现场人员，不假定已接管或充电，不自动离桩。 |
| `HANDOFF_PENDING` | 已对准且自研运动授权已撤销，等待约定的原厂或现场接管确认；不再发自研运动命令。 |
| `HANDED_OFF` | 已取得有效接管确认；本期任务结束，自研导航与遥控继续禁用。 |
| `PAUSED_FAULT` | 故障已锁存且运动被禁止；仅执行本地记录、提示和已验证的静止处置，等待现场检查或约定回收。 |
| `CANCELLED` | 任务取消且停车完成；不再补拍、不自动返桩、不因网络恢复而继续运动。 |

- `WAITING_OBSTACLE` 仅在障碍持续消失、传感器与定位有效、剩余预算充足、原任务仍有效且路线允许时自动回到原任务状态；稳定时间和等待上限在 M2 前冻结。
- 定位失锁、控制链路故障、临界电量、停车失败、原厂控制权未知和无法安全返桩的超预算失败均进入 `PAUSED_FAULT`；仅故障信号恢复不能解除锁存。
- 锁存故障须经已验证的现场操作通道确认处置，重新执行所需自检并取得新授权。没有该通道时保持停机，按出发前预案回收。
- 重启后从检查点恢复的是任务记录和已完成成果；不得恢复旧速度、旧遥控租约或直接恢复行走。重新确认状态及授权后才能执行剩余任务。
- 中途恢复定位仅允许使用已经验证的当前位置重定位流程；不能在任意位置重用入口初始位姿。无法确认当前位置时维持锁存，现场移回已知初始化点或按预案回收。
- 任务取消与“返桩”是不同命令。取消先停机；只有另行取得有效返桩授权且健康条件满足时才可返桩。
- 取消先受理并立即撤销运动，不等待相机或写盘完成才停车。确认停稳后，载荷取消在有限时间内返回终态；无法确认的动作标为 `UNKNOWN` 并写入取消结果，不阻塞停车或盲目重发。不能确认停稳则进入 `PAUSED_FAULT`，不能报告取消完成。
- 任务结束原因、巡检点业务完成度、对准结果、交接结果和成果同步状态分别保存；低电提前返桩后对准成功，仍须保留未完成点和提前结束原因。

### 5.3 并发事件优先级

同一周期出现多个事件时，先执行最高优先级事件的运动约束，其余事件仍入日志。所有有效停车/禁止条件取交集，任何运动请求不得抵消停车约束；低优先级动作不得解除高优先级故障锁存。

| 优先级（高到低） | 事件 | 本地结果 |
|---|---|---|
| 1 | 独立急停、原厂强制接管、控制权未知、停车机制失效 | 撤销全部自研运动授权并锁存；原厂占有/未知时只使用原厂约定的独立停车手段，不以自研 SDK 命令争抢控制权。 |
| 2 | 防撞停车、机内控制/关键传感器失联、定位无效、指令过期、临界电量 | 立即禁止对应运动并停车；仅普通障碍等待允许按约定条件自动恢复，临界电量按静止处置预案执行。 |
| 3 | 有效取消/暂停、人工接管、当前 `TELEOP` 会话失效、关键记录不能持久化 | 先撤销对应授权并停车；按事件进入取消、人工暂停或故障锁存，不自动进入另一运动模式。 |
| 4 | 气体等现场危险事件 | 执行出发前配置的现场处置；撤离动作必须仍满足定位、防撞、控制权、可达性和剩余预算条件，否则停机并按预案处置。 |
| 5 | 等待或对准预算耗尽 | 结束当前动作；仅在仍有合法返程且能量充足时转入已授权返桩，否则静止处置并锁存；不得继续重复尝试。 |
| 6 | 达到返桩阈值、正常巡检完成 | 终止后续非必要巡检，健康及路径条件满足时返桩；不能越过更高优先级停车约束。 |
| 7 | 抓拍、补拍、常规任务推进 | 在剩余预算和当前授权允许范围内执行。 |

外网断开和外网恢复不属于运动优先级事件；仅产生本地同步状态变化。上表的“停车”不代表允许自行关机或改变原厂步态，静止姿态按原厂能力与现场验证结果确定。

### 5.4 运动授权与失效停车

- 自研授权至少包括 `NONE`、`NAVIGATION`、`TELEOP`、`ALIGNMENT`；另记录原厂控制状态 `RELEASED`、`OWNED`、`UNKNOWN`。原厂为 `OWNED` 或 `UNKNOWN` 时，所有自研授权必须为 `NONE`。
- 切换运动来源采用“撤销旧授权 → 发停车请求 → 验证停稳 → 校验新来源条件 → 发放新授权”的顺序；任一步超时即锁存故障，不能同时放行两个来源。
- 每次授权分配新的授权代号，绑定来源、任务或会话及有效期。迟到命令、旧代号命令、乱序命令和过期命令均拒绝执行。
- 自主运动授权由机载任务和健康模块持续维持，与外部连接和 Web 会话无关；内部授权续期失败则按控制故障停车。原厂接管与释放不会自动新建自研授权。
- Nav2、人工遥控、桩前对准仅提交速度请求，唯一自研运动通道为“仲裁器 → Collision Monitor → 底盘桥接 → Unitree SDK2”。抓拍减速以约束输入参与仲裁，不能直接调用底盘。
- 新鲜度检查使用机载单调时钟计算超时；保留传感器原始采集时间用于配准与追溯。网关或中间节点重复转发旧数据不能刷新其有效期。
- 底盘桥接同时检查授权、输入命令年龄、自身循环时延及关键健康状态；失效时输出经验证的停车请求，并记录原因和实际停稳反馈。
- Collision Monitor 的点云/TF 过期处理、方向相关停车区及底盘桥接超时必须共同配置；任何一个环节正常不意味着其他环节的失效已被覆盖。
- **桥接进程或整个 Orin 失效时，不能依赖其继续发送 `StopMove()`。** M0 必须查明并验证底盘接收端是否提供命令失效、通信看门狗或其他独立停车机制，以及其触发条件与最大停车时延。
- 不能确认上述独立停车能力时，不放行自主实机运动；保留独立人工急停，但不能用它替代无人在线干预条件下的失效停车保证。
- M2 必须注入：杀死桥接进程、停止仲裁/防撞输出、使关键输入过期、断开 SDK 通信及模拟 Orin 失联，验证无陈旧指令继续生效、停车距离达标和故障保持锁存。
- 独立人工急停、原厂停车、软件停车的作用范围、可观测反馈及复位操作分别记录；急停复位只解除急停条件，不自动恢复任务运动。

### 5.5 定位健康与运动门控

- 由定位健康监控模块统一输出健康状态，任务管理器、运动仲裁器及桩前对准模块共同消费；具体消息字段遵循接口节，禁止各模块自行解释“定位正常”。
- 状态至少包含 `INITIALIZING`、`VALID`、`DEGRADED`、`INVALID`，附地图版本、定位会话、数据时间、最近成功定位时间及结构化原因码。
- 检查项至少包括：点云/IMU/里程计/TF 新鲜度、里程计连续性、全局匹配是否成功、地图版本一致性、全局校正幅度、距上次有效地标的行驶距离及各诊断的有效性。
- 区分 TF 持续发布与新的全局定位成功；重复发布旧变换不能刷新“最近成功定位时间”。质量分数或协方差仅在实测证明能反映风险后用作阈值依据。
- `VALID` 才允许从初始化进入自主运动；任务受理后的静止自检和初始化不受此限制。`DEGRADED` 仅能执行事先验收的限速及有限距离策略；`INVALID` 禁止自研运动，先停车再处理定位恢复。
- 全局大幅校正、错站嫌疑、地图版本不符或超过无校验距离时先暂停；重新识别到标签不自动解除锁存，须验证位置一致性和任务进度。
- 采集任务记录定位健康和位姿有效性。无效定位期间的数据可以保留原始记录，但不得伪装成可靠的设备点位或泄漏源位置。
- M1 冻结状态判据与测量方法，M2 前冻结运动门控阈值；M3 根据标签试验补齐地标相关阈值，未通过对应试验的路线不得启用相关降级行驶策略。

### 5.6 低电量与故障等待预算

- 电量策略在机载侧持续计算；输入包含电池状态有效性、已验收路线的剩余返程代价、当前载荷实测能耗、桩前定位/对准成本和安全余量。
- 出发前确认电量足以完成计划任务及返桩，并为预定重试和安全停留留出预算；电池数据无效、返程不可达或预算不足时拒绝任务启动。
- 返桩触发条件采用经场测校准的剩余能量预算及迟滞；首次触发后停止非必要抓拍和新巡检点，不因短暂电量回升切回巡检。
- 分别设置巡检阻塞等待上限、返程阻塞等待上限、定位恢复上限、单次对准上限、累计对准时间及总重试次数；等待和重试均计入同一任务的能量预算。
- 阻塞期间持续重算返桩能力。允许沿已验收原路返程且路径可达时可结束巡检返桩；首期不为绕过障碍临时生成未经验证的绕行或倒退路线。
- 返程本身被阻断时，保持防撞停车，仅在剩余时间和能量预算内等待；预算耗尽后锁存故障并执行出发前约定的静止处置与人工回收流程。
- 对准失败只有在下一次尝试的时间、能量、空间和传感器条件全部满足时才可重试；取消、人员闯入、临界电量或控制权未知立即终止本轮授权。
- 临界电量阈值为进入静止处置保留必要能量；不得将“等待人工”实现成无时限的高耗能动作，也不得在未验证原厂要求时自行断电。
- 离线运行中无法通过远程指令解除预算上限。若现场无法安全停留，则该路线不满足本期离线任务准入条件，须先修改路线或现场处置方案。
- M0 记录电池数据接口和原厂低电保护；M2 前给出保守试验预算，M4 前以完整路线实测冻结正式值。所有未确认值标为 `TBD`，并列责任人、验证用例和冻结关口。

### 5.7 原厂对准结果与接管确认

每个 `dock_id` 保存地图/配置版本、桩前预对准位姿、目标位姿、允许接近方向、标签或原厂定位标识、搜索范围、容差及退出位置。任务仅从已发布且存在合法返程的桩中选择，不能在线寻找未配置桩位。

1. 路线执行器沿批准返程路径到达预对准位姿，停稳并撤销导航授权。
2. 近场定位优先使用已验证的原厂相对位姿接口；不可用时验证原装相机观测专用 AprilTag，并标定标签到目标对准位姿的固定变换。目标 ID 不符、观测过期或几何条件不足时禁止进桩。
3. 对准控制器使用连续 `odom` 与新鲜相对位姿闭环低速运行，仍经过同一仲裁和防撞链路。对准误差、角度、持续稳定时间和停稳反馈同时达标才产生 `ALIGNED`；桩体不得通过全局关闭防撞来排除，须在受限进桩区域验证目标过滤及人员/其他障碍监控。
4. 出发前选择 `alignment_only`（仅对准）或 `local_handoff`（机载交接）模式。两种模式均须先确认停稳并撤销全部自研运动授权，再分别进入 `COMPLETED_ALIGNED` 或 `HANDOFF_PENDING`；保持自研运动禁用，后续新任务仍须自检和新授权。不能把缺少原厂接口隐式当成交接成功。

| 状态 | 判定与显示 |
|---|---|
| `ALIGNED` | 对准误差与停稳条件达标，只能显示“对准完成”。 |
| `HANDOFF_PENDING` | 自研运动授权已撤销并已提交交接请求，尚无有效接管确认；显示“等待接管确认”。 |
| `HANDOFF_ACCEPTED` | 收到本次交接对应的原厂确认或预先约定的有效现场确认；显示“已交接”。 |
| `HANDOFF_FAILED` | 原厂明确拒绝或交接条件不满足；记录原因，保持自研运动禁用。 |
| `HANDOFF_UNKNOWN` | 超时、确认丢失、原厂状态不可读或重启后无法确认控制权；保持自研运动禁用并锁存。 |
| `RELEASED` | 已取得原厂明确释放证据；仅表示可重新执行自检和申请授权，不自动恢复运动。 |

- 每次交接关联唯一交接编号、`dock_id`、任务及本次授权代号，明确确认来源、有效期、拒绝原因和超时结果；旧确认不能完成新交接。
- `ALIGNED` 不等于 `HANDOFF_ACCEPTED`，两者均不等于充电已开始。上位机与离线日志分别记录，不合并成单一“充电成功”。
- 若首期接口仅支持人工确认，必须在出发前声明“现场确认交接”及人员到场安排；机器人可独立完成对准，但不得宣称能够自动接管或保证自动开始充电。
- 离线交接必须由机载可访问的原厂接口或已验证的现场操作通道完成，不能等待 Web 后端确认。没有可用确认通道时进入未知/失败状态并执行约定回收流程。
- 交接被拒绝或状态未知时，不通过重新发送运动命令试探控制权。只有原厂明确释放并完成现场处置与重新授权后，才允许新的自研对准任务。
- 充电触点、充电启动、充电状态确认和离桩仍由原厂系统负责。原厂接管后的人员/障碍监控与停车责任须在 M0 记录并验证，不假定原有自研防撞链路仍能拦截原厂运动。
- M0 冻结交接能力与确认方式；M4 前验收成功、拒绝、确认丢失、超时、取消、重启及控制权释放。没有确认链路的部署只验收“对准完成”，不验收“自动接管”。

## 6. 巡检载荷与成果

定位、导航和载荷节点独立运行。载荷通过异步动作及事件与任务管理器交互，设备重连、图像处理、磁盘写入或气体通信超时不得阻塞导航和停车。故障可以导致任务降级或中止，但不得阻塞运动撤权。

### 6.1 行进中云台拍摄

设备配置包含 `asset_id`、目标地图坐标或示教预置位、路线段/方向、允许拍摄区间、取景约束、是否允许停车、重试次数和关键性。结果记录 `mission_id`、点位执行 ID、地图/配置版本、帧时间及可信度、实际机身位姿、云台反馈角度、文件校验值和质量状态。

1. **提前进入拍摄窗口。** 根据当前路线段、方向和连续沿线进度触发，窗口提前量覆盖云台转动、稳定与采集延迟。示教预置位只在验证过的位置范围使用；三维目标瞄准由采集时刻机身位姿及 `base_link → 云台基座 → 云台轴 → 相机光学坐标系` 计算，并补偿机身转动。
2. **抓拍与机载核验。** 在窗口内以已验证速度拍摄，检查设备动作反馈、有效帧、文件落盘、曝光与清晰度等已实现指标，必要时连拍择优。首期人工图像质量验收在返程后进行，不依赖运行中人工在线判图；尚未实现的自动语义核验标为 `REVIEW_REQUIRED`，不能当作已通过。
3. **补拍。** 失败时仅在同窗口及剩余预算内减速重试，允许的点可停稳补拍。关键点仍失败时执行预装的暂停/返桩策略；非关键点可记失败后继续。机载无法确定图像质量且窗口将结束时，可按配置主动停稳补拍，禁止等待 Web 审核。抓拍结果未知时先按动作 ID 查询与对账，不盲目重复。

拍摄节点只请求速度上限和停车需求，由任务管理器确认后交给统一运动链路。错过窗口或返程经过相同设备时，按显式的点位执行策略处理，不能因位置相近重复计为完成。

### 6.2 气体与其他传感器

- 气体在机载持续采样、落盘，包含气体种类、浓度、单位、量程、有效性、原始时间及关联位姿；按任务配置支持定点停留。预热、校准、采样流量和通信状态参与诊断；失效值不得记作正常零值。
- 实测安装位置的响应时间和采样管输送延迟。报警记录包含位置不确定度，结合车速、响应时间和气流说明；报警时位置不能直接当作泄漏源坐标。
- 气体门限、传感器失效处理和报警动作作为出发前配置冻结。离线时机载立即判定并执行；只允许已获现场认可且定位/路径有效的撤离动作，否则停止、锁存并记录。本地提示的实际形式以实机硬件为准；告警联网后补传，不能承诺运行中送达平台。
- 涉及爆炸危险区域时，运行和充电前按现场分区核对整机、载荷及充电设备的适用性；未确认则该区域不纳入自主路线。机器人采集与现场既有保护/联锁分别管理。
- 新增载荷沿用统一数据/诊断/异步动作接口，重新核验供电、带宽、重量、外廓、散热、步态、雷达遮挡、停车距离与桩前净空。

## 7. 离线任务包、接口、数据与 Web 同步

### 7.1 离线运行与任务准备

现场巡检期间按**无外部网络**设计；机器人内部雷达、底盘和载荷网络仍可用。地图、路线、标签、设备点、桩位、标定、策略和启动授权必须在出发前完整落盘。机载任务管理器独立运行，不依赖 Web 租约、后端心跳、云端鉴权或在线 NTP。外部连接消失不构成已授权离线任务的暂停原因；机载故障处置仍按任务状态机执行。

入口或维护位置存在连接时，`robot_gateway` 可主动通过 WSS 交换命令与状态，通过 HTTPS 传输任务包和媒体；不能假定充电座有网络。巡检中不提供实时 Web 遥控、状态或远程告警承诺。告警在机载记录并执行本地策略；现场提示能力由 M0 核实。Web 持续显示“最后同步时间”和“离线／数据已过期”，不得用缓存状态表现为实时状态。

任务准备分为“接收任务包—校验入库—持久化签收—本地检查—一次性启动授权—启动”。签收只表示包已完整持久化，不表示运动已授权。任务包在暂存目录下载，逐文件验证摘要和清单，确认机器人型号、软件兼容、坐标与版本关系后激活；不完整或不匹配的包不得成为当前任务输入。活动任务固定绑定同一包，更新仅供后续任务使用。

首期由授权操作员在入口完成任务选择与放行，可使用已连接的维护界面或经确认的机载操作入口；M0 固定实际入口。授权绑定 `robot_id`、`mission_id`、`bundle_id` 和当前 `boot_id`，限定一次启动并持久化消费结果。机器人重启后原运动授权失效，恢复进度后必须重新授权。若采用定时启动或带绝对失效时间的授权，必须具备可验证的本地时钟；时钟质量不足时拒绝该方式，使用现场明确操作，不把 NTP 可达性设为前提。

进入运动前按状态机完成任务包完整性、地图与标定兼容、入口定位、传感器健康、底盘控制权、电量以及存储预算检查，任何必需项未通过都禁止运动并给出原因。启动受理可以进入自检和定位阶段，不等于已获运动许可。任务中禁止临时请求云端下载缺失路线、地图、设备配置或解锁授权。

### 7.2 标识、版本与最小数据契约

接口采用显式 `schema_version`，未知主版本或缺少必填字段即拒绝。实际 ROS 2 类型在 M0 固化；下表为必须保留的语义。版本、阈值和设备参数由已验收配置提供，不在代码或前端中隐含默认值。

| 字段 | 唯一性与用途 |
|---|---|
| `robot_id` / `boot_id` | 设备稳定标识／本次机载启动标识；跨重启单调时间不得直接比较。 |
| `bundle_id` | 不可变任务包标识，关联清单摘要、文件摘要和兼容声明；内容变化生成新标识。 |
| `map_version` | 同版地图数据库、栅格及地图坐标定义；不是任务包或整个配置的版本。 |
| `config_version` | 不可变配置快照，包含外参、标定、路线窗口、桩参数、阈值和策略，引用 `map_version`。 |
| `mission_id` | 一次巡检执行的标识；重复执行相同路线仍产生新任务，不由重试请求重新生成。 |
| `request_id` | 一次业务命令的幂等键；重发同一命令保持不变，并校验载荷摘要。 |
| `action_id` | 任务中的一次具体导航、抓拍或对准动作标识；有意识的新尝试使用新标识并记录 `retry_of`。 |
| `visit_id` | 本任务中计划执行一次设备点巡检的标识，绑定路线段、方向与计划经过次数；多次补拍动作仍归同一次巡检点执行。 |
| `asset_id` / `media_id` | 稳定设备点标识／单个媒体对象标识；同设备多次拍摄产生不同媒体对象。 |

| 对象 | 最小字段 |
|---|---|
| 任务包清单 | `schema_version, bundle_id, robot_compatibility, software_compatibility, map_version, config_version, route_ids, files[{path,size,sha256}]`；清单规范化内容的摘要和发布签名存于外部封套，不对包含自身摘要的内容递归求摘要，本地可信公钥校验发布来源。 |
| 任务记录 | `mission_id, robot_id, bundle_id, map_version, config_version, route_id, state, progress, created_at, terminal_reason`。 |
| 设备点配置 | `asset_id, segment_id, direction, target_pose或preset_id, capture_window, required, quality_rule, retry_policy, stop_allowed`。 |
| 动作请求 | `schema_version, mission_id, action_id, visit_id（巡检载荷动作）, action_type, target, timeout_ms, retry_of`；超时参数来自配置，不代表设备已停止执行。 |
| 动作反馈／结果 | `action_id, phase, result_code, observed_state, media_ids, error_code, retryable, event_seq`；结果区分成功、失败、已取消、结果未知。 |
| 采集记录 | `mission_id, action_id, asset_id, sensor_id, boot_id, sample_time, received_mono_ns, time_quality, frame_id, pose, pose_quality, value或media_id, validity`。 |
| 状态事件 | `robot_id, boot_id, event_seq, mission_id, state, fault_code, mono_ns, utc_time, time_quality`；`event_seq` 由本地数据库持久化递增。 |
| 定位健康 | `boot_id, localization_session_id, map_version, state, observed_mono_ns, last_match_mono_ns, odom_age_ms, tf_age_ms, correction_translation, correction_yaw, distance_since_landmark, reason_codes`；无有效测量的字段标缺失，不能填零冒充健康。 |
| 运动许可/请求 | `boot_id, control_epoch, source, mission_id或session_id, seq, generated_mono_ns, valid_for_ms, vx, vy, wz`；许可另含允许方向与速度范围，接收端按状态与本地时钟校验。 |

采集时间同时保留设备原始时间及其到机载时钟的映射质量；`utc_time` 可为空，不能在时钟未校验时伪造精确墙上时间。控制新鲜度、动作超时和看门狗使用本机单调时钟。位姿必须对应采集时刻并标注质量；无法可靠关联时保留数据、明确无效关联，不使用上传时的位置或时间替代。

### 7.3 机载模块接口与动作结果

| 接口 | 契约 |
|---|---|
| `PrepareMission` / `AuthorizeMission` / `StartMission` | 分别负责固化任务输入、记录一次性授权、消费授权并开始执行；返回 `request_id, mission_id, accepted或rejected, reason`。受理确认在事务持久化后发送。 |
| `PauseMission` / `ResumeMission` / `CancelMission` / `ReturnToDock` | 携带 `mission_id, request_id`；状态前置条件由任务状态机校验。恢复须有当前有效的任务授权，重启或授权撤销后重新授权；取消遵循第 5.2 节，先停车，再在有界时间内对在途动作分类并返回结果。 |
| 云台 `AimAndCapture` | 接受目标与取景约束，反馈瞄准、稳定、曝光、保存阶段；成功须返回已提交的 `media_id`、实际角度、帧时间和质量结果。 |
| 气体 `GasSample` / `GasHealth` | 发布原始值、单位、采集时间、有效性及预热/校准/流量/通信状态；定点停留通过任务管理器协调。 |
| 桩前 `AlignDock` | 接受 `dock_id` 和绑定配置，反馈目标一致性、相对位姿及阶段；完成对准、交接确认、交接失败分别记录，不能以超时推断成功。 |
| `QueryAction` / `CancelAction` | 查询最后已知状态／请求取消；取消请求送达不等于已取消，必须取得终态或进入 `UNKNOWN` 并由任务策略处置。 |
| `SpeedConstraint` | 载荷仅提交有作用域与本地有效期的速度约束；任务管理器合成约束，实际运动继续经过统一仲裁和防撞链路。 |

定位健康话题和运动许可接口按上表发布并有明确存活超时。Nav2 标准速度消息通过源端适配器绑定当前授权；经过标准 `cmd_vel` 接口的链路仍必须与当前许可代号关联，授权切换时先禁用输出、清理旧队列、确认停稳，再接受新代号数据。不得简单给缓存速度补新时间戳后执行。查看、配置发布与操控分别鉴权，维护控制同时仅一个持有者，命令记录操作员身份和状态转换。机载任务命令采用明确的请求/受理/最终结果接口，长时导航、抓拍和对准采用可取消的 ROS 2 action；数据与诊断采用话题。

最小错误码包含 `INVALID_STATE`、`BUNDLE_INVALID`、`VERSION_MISMATCH`、`NOT_AUTHORIZED`、`STALE_COMMAND`、`LOCALIZATION_INVALID`、`SENSOR_STALE`、`CONTROL_UNKNOWN`、`TIMEOUT`、`CANCELLED`、`RESULT_UNKNOWN`、`STORAGE_LOW`、`IO_FAILURE`、`ENERGY_INSUFFICIENT` 和 `DOCK_TARGET_MISMATCH`。错误码、可重试性和当前状态一起返回，不能由前端猜测是否应重发。

动作请求先入库，再下发设备；反馈和终态按 `action_id` 关联。节点超时或断开时不得把“未收到成功”当成“确定未执行”。设备支持按动作标识查结果时先查询；不支持时进入 `UNKNOWN`，先由持久化媒体和设备状态机载对账，无法解决时按预装策略留待返程或现场复核，不能依赖在线人工确认。特别是抓拍结果未知时不得盲目重发；只有已确认失败，或策略明确批准一次新尝试，才产生新的 `action_id`。

上述先入库规则适用于派发新的业务动作。停车、撤权、取消中的停止动作走独立快速通道，不能等待事务、媒体队列或载荷响应；停止结果随后记录，持久化失败时明确报告记录失败，禁止恢复新业务动作。

最小受理消息示例（省略传输层认证；示例标识不代表实机配置）：

```json
[
  {"schema_version":1,"type":"PrepareMission","robot_id":"robot-A","request_id":"req-prepare-001","bundle_id":"bundle-004","route_id":"route-A"},
  {"schema_version":1,"type":"CommandResult","request_id":"req-prepare-001","mission_id":"mission-001","status":"accepted","state":"READY","persisted":true}
]
```

最小抓拍结果示例：

```json
{"schema_version":1,"mission_id":"mission-001","action_id":"capture-asset-01-pass-01","visit_id":"visit-01","asset_id":"asset-01","phase":"terminal","result_code":"SUCCEEDED","media_ids":["media-001"],"quality_status":"REVIEW_REQUIRED","event_seq":208}
```

`SUCCEEDED` 在此仅表示约定抓拍动作与文件提交成功；图像业务合格性单独记录为通过、未通过或待人工复核，不能把动作成功直接计为巡检点验收通过。

### 7.4 持久化、去重与重启恢复

首期采用本地 **SQLite + 媒体文件目录**。SQLite 保存任务包索引、任务、命令收据、动作、检查点、事件、媒体索引和同步水位；软件/配置回退不回滚业务数据库与已消费授权；启用 WAL 和关键事务同步写入，部署时验证异常断电后的恢复能力。媒体写入及上传在独立工作队列执行，设定有界队列和资源配额，不阻塞导航控制与停车。

命令表以 `(robot_id, request_id)` 唯一约束，保存请求摘要、受理结果和关联 `mission_id`。创建任务、写入命令收据、消费启动授权及状态变化分别在对应的同一事务中提交后才确认。重复同 ID、同内容返回原结果；同 ID、异内容拒绝。去重记录至少覆盖任务和审计保留期，清理后也不能通过历史会话重放命令。重启或响应丢失后重发启动请求只能查询同一任务，不创建第二次执行。

检查点至少保存包及配置版本、当前路线段与方向、已完成/未完成设备点、在途动作、返桩原因和数据提交状态。关键状态变化后提交检查点；连续气体数据可按有界批次写入，记录尚未落盘区间和重启后的数据缺口。不能以“进度百分比”作为恢复依据。

大媒体文件不能与 SQLite 作为同一事务原子提交，使用以下提交协议：

1. 先登记 `media_id`、对应 `action_id/visit_id`、`PENDING` 状态、临时/最终路径及采集元数据；元数据包含源时间、时间质量、坐标系、位姿及有效性、云台反馈与质量结果。向同文件系统内的临时文件写入。
2. 完成文件写入并同步文件，将实测尺寸和摘要持久化到 `PENDING` 记录；随后原子重命名到最终路径并同步目录。
3. 在数据库事务中把媒体标为 `COMMITTED`，关联采集元数据并推进动作状态；只有该状态的媒体可用于成果统计和上传。
4. 启动恢复时对账数据库与文件：`PENDING` 且文件、摘要和采集元数据均可核实的完成重命名或补交索引；仅有图像而缺少可核实元数据的隔离为待复核，不能自动判为有效巡检成果。残缺临时文件隔离；索引存在但文件缺失的标记损坏并告警；无索引文件隔离核对。

重启后默认禁止运动，先恢复数据库、核对任务包、扫描未决动作与媒体，再重新检查定位、传感器、底盘和电量。检查点仅恢复业务进度；原动作是否完成不明时保持未决，待查询或确认。通过检查并取得新的本地授权后，任务管理器生成续作计划，不能从旧速度命令、旧 Web 请求或旧动作队列自动恢复运动。

### 7.5 存储预算与成果保留

出发前按路线设备数、预计照片量、气体频率、最长离线时长和故障日志估算存储，另留关键数据库及返程记录余量；M0/M1 完成容量估算，预算和水位在 M3 载荷联调前冻结；M2 试验也须预留日志与停车记录空间。媒体、气体、事件、调试日志分别设配额，调试 rosbag 默认仅用于批准的采集任务，不能无限占盘。

| 情况 | 行为 |
|---|---|
| 出发前容量不足 | 拒绝启动，提示所缺容量与可清理数据类别。 |
| 运行中达到预警水位 | 停止非必需调试采集，限流可选媒体；持久化告警，按任务策略决定提前返程。 |
| 达到停止巡检水位，但关键记录余量仍可写 | 停止新增巡检动作；健康、能量和合法返程均满足时进入提前返桩，否则停车锁存。返程记录使用预留配额。 |
| 关键数据库/记录无法持久化 | 立即撤销运动并停车锁存，停止派发新业务动作；用可用的本地提示报告，不能宣称故障已可靠落盘。写盘失败不得阻塞停车。 |
| 删除历史数据 | 仅删除已获后端持久化确认且达到保留期的数据；未上传成果不得为腾空间静默覆盖。无网时容量不足按上述策略处置。 |

任务成功、成果完整、上传完成分别记录。允许“任务已结束、成果待补传”；媒体缺失、气体缺测或待复核不能被汇总界面隐藏。保留期、预警/停止水位和允许丢弃的数据类别是显式配置，无已验收配置则不得自主出发。

### 7.6 有连接时的同步与控制边界

联网先认证设备并交换协议版本，随后同步完整机载状态和持久化 `event_seq` 水位，再补传事件、气体数据和媒体。后端以媒体标识及摘要幂等接收，只有文件完整校验并持久化后返回确认；机器人收到确认后写本地同步状态。上传中断可重试或续传，不能因 HTTP 请求发出就标为完成。后端事件确认使用最高连续水位，缺口应补发，不跳过未确认记录。

恢复连接本身只触发数据同步，不自动启动、继续、切换控制权或执行后台积压命令。任务包下载与激活、任务启动和运动控制分开处理。服务端离线队列仅可保留查询、包分发和数据同步意图；启动、继续、遥控及其他会改变运动状态的命令不得离线排队后重放。

联网维护时如需控制，机器人签发绑定 `boot_id` 的短时会话和挑战，按本机单调时钟判断有效期；断开、重启或授权撤销立即失效。命令须引用当前挑战、顺序号和明确的操作员授权，机器人校验当前任务状态后受理。旧会话、旧挑战和顺序倒退一律拒绝，重新连接必须重新授权。离线自主任务的授权与维护遥控会话相互独立。

联合验收至少覆盖：任务包缺失/损坏/版本不符拒绝启动；断开外网完成已授权路线；服务端不可达及无 NTP 可达性仍按本地时间质量规则工作；离线告警本地执行并补传；网关或主机重启后的启动去重；媒体提交各步骤断电恢复；未知抓拍结果对账；磁盘水位处置；重复上传/确认丢失；重连旧命令拒绝；Web 离线过期标识。测试阈值和次数引用冻结的验收矩阵。

## 8. 开发顺序与阶段准入

首期目标是在管廊内**无外部网络条件下完成整趟自主任务**。任务、地图、路线、设备配置和返桩配置必须在出发前已完整保存在机载侧；运行期间不依赖 Web 会话、云端计算、在线鉴权或媒体上传。

外部网络不可用是正常工况，不触发任务暂停。车内传感器、SDK/DDS 控制链路或必需模块失效属于运行故障，按已冻结的健康状态和失效策略停车或降级，不能用“离线运行”豁免。

| 阶段 | 工作与交付物 | 通过条件与下一阶段准入条件 |
|---|---|---|
| M0 接入与失效边界验证 | 确认整机/背包/载荷型号和原厂接口；锁定候选系统与代码版本；完成台架接入、静止/直行/转弯录包，记录点云字段、时钟、IMU、TF、QoS、SDK 状态及控制权语义；验证原厂失联停车能力。 | 两路点云可区分，DLIO 所需时间信息及 IMU 可用，坐标和时序可解释；形成接口核查表、未决项和底盘指令失效证据。允许继续离线回放与原型开发，不能仅凭接口连通放行自主运动。 |
| M1 定位、地图与离线任务原型 | 在录包与有人监护的采集中验证 DLIO、点云去畸变、RTAB-Map、地标和固定路线；制作同版本地图/路线/点位/标签/桩配置包；验证机载任务、记录与重启恢复原型。 | 使用独立真值统计入口初始化、往返误差和错站；明确定位健康信号、地图发布规则及路线约束。M0/M1 可用于发现能力边界，实测结果不自动成为交付要求。 |
| M2 受控导航与故障停车 | 冻结受测速度/方向/载荷、停车范围、定位降级条件、控制权状态机和失效边界后，验证唯一运动通道、固定路线约束、障碍等待及必需模块故障。 | 对桥接进程退出、Orin 掉电或经说明的等效失联、SDK 网络断开，均有下游停车证据；定位失效、传感器失效或未授权重启不得继续自主运动。未通过失效准入条件时继续台架/回放修正，不进入全程自主测试。 |
| M3 地标、载荷与离线业务 | 按相同路线对比有无地标，测试往返、遮挡和相似设备；联调移动拍摄、补拍、气体定位关联、持久化记录及容量管理；整段保持外部网络关闭。 | 无外部网络仍可调度、采集、告警留存和更新本地任务进度；错误定位不得导致错站被判成功；载荷故障与写盘异常按约定策略处理，不能阻塞停车链路。 |
| M4 全程验收与交付 | 在交付标准已冻结后，以实际载荷、地图、路线、功耗和散热条件，完成离线整趟巡检、低电返桩、对准交接及恢复联网上传的综合复测。 | 验收矩阵所有必选项达到事先约定目标，未决项有关闭证据；交付配置、软件版本、地图版本与受测版本一致。对准与交接结果按真实状态分别报告，不将其等同于充电成功。 |

M0/M1 的运动采集仍需采用已批准的受控方式。M2 的“受控导航”不是在未验证停车能力时开始自由巡检；底盘失联处理及独立人工急停应先有台架或受限实机验证证据。

### 8.1 阶段冻结与变更

- **M0 结束：** 固化实机清单、接口实测记录、候选依赖版本和阻断项；无法取得的关键接口须登记替代方案及验证责任，不能按“原厂应当支持”关闭。
- **M1 结束：** 固化首条验证路线、地图版本、真值测量方案、定位健康输入和固定路线执行方式；采样数量、测试条件和判定方法先于对应正式测试确定。
- **M2 受控上机前：** 冻结本轮允许的速度、动作方向、外廓、停车边界、链路超时、故障优先级和恢复授权条件。阈值由现场风险边界与实测能力共同确定，未填写时视为未放行。
- **M4 开始前：** 由现场需求方确认交付目标、统计口径、样本数、通过阈值及允许的降级范围；测试后不得仅因未达标而将阈值改成实测结果。
- 软件、载荷安装、地图、路线、步态、限速或停车策略变更时，记录影响范围并重测受影响条目；保留先前结果，形成新版本验收记录。

### 8.2 验收记录格式

每项记录至少包含：`case_id`、需求编号、需求目标、允许工况、软件/配置/地图版本、测试方法、真值或对照依据、样本数量及覆盖条件、通过阈值、实测结果、失败样本、责任角色、冻结节点、结论及证据路径。

“需求目标”和“实测能力”分列保存：前者由现场需求方确认，后者由测试获得。各项样本数和阈值当前均为待确认项，必须在表列冻结节点前填写；空白、仅有平均值或缺少失败样本，不能作为通过证据。

位姿真值采用经确认的现场测量点、独立测量或可复核标尺；不得使用被测 SLAM 自身轨迹作为唯一真值。停车试验应记录故障/障碍触发至实际停稳的全过程，并说明测量误差和时钟对齐方式。

| 验收项 | 需求目标 / 实测能力记录 | 方法及真值或对照 | 样本数与覆盖要求 | 通过阈值 | 责任角色 | 冻结节点 |
|---|---|---|---|---|---|---|

| Q06 | 任务启动与本地人工授权方式、现场可用告警/急停、无外网作业流程 | 现场需求方、任务开发 | M2 受控上机前 | 现场操作演练记录；不能依赖运行时 Web 连通才可启动/停止必要流程。 |

未决项不能只写“现场确认”后长期悬置。每项须说明影响范围、下一步验证和关闭期限；影响运动或失效边界的未决项阻断对应实机阶段，其余项可继续模拟端、回放或台架工作。

最终交付包包含已冻结方案、依赖与配置清单、地图/路线/标签/设备/桩配置包、验收记录及原始证据、离线操作与故障处置说明。部署时核对交付包版本，避免现场配置与验收版本不一致。
