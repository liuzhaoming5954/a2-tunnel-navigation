# A2-PRO 地下管廊定位导航与巡检方案

**版本 v0.3 · 2026-11-03 · 开发基线**

## 1. 初版范围

架构、软件选型和巡检行为已收敛，可以开始开发。实机接口和性能指标由首轮采集与场测确认，通过验收后再放行自主巡检。

| 项目 | v0.3 决策 |
|---|---|
| 运行场景 | 单层、预先建图的地下管廊。从已知入口启动，沿固定路线巡检，任务结束或电量不足时导航至原厂充电座并完成对准。 |
| 运行平台 | A2-PRO 算力背包 NVIDIA Jetson Orin（ARM64）。底盘执行宇树原有步态。PC2 在必要时仅转发传感器数据或桥接控制。 |
| 传感器 | 原装前后禾赛 JT128、原装前置光学相机及补光灯，以及上装云台相机和气体传感器。里程计优先使用前雷达内置 IMU，若实机未输出可用数据，则验证 A2 机身 IMU 方案。 |
| 软件栈 | ROS 2、禾赛 ROS 驱动、DLIO、RTAB-Map、Nav2、`apriltag_ros`、Unitree SDK2。 |
| 巡检行为 | 行进中按拍摄窗口给固定设备拍照，必要时停稳补拍。沿线采集气体，记录数据和位姿。完成后导航至原厂充电座并完成定位与对准。障碍出现时减速或停车，持续堵塞时暂停并告警。 |
| 上位机 | 现有 Web 平台通过 Orin 网关实现任务操控、人工遥控、状态与成果展示。 |
| 范围边界 | 自动绕行、跨层及楼梯自主通行、FAST-LIVO2 视觉惯性融合留待后续评估。 |

## 2. 数据流与接口

| 输入 | 处理 | 输出或用途 |
|---|---|---|
| 前 JT128 原始点云、优先用前雷达 IMU | 禾赛驱动 → DLIO | `nav_msgs/Odometry` 和 `odom → base_link`，供定位和控制使用 |
| 前雷达点云、DLIO 里程计、已通过校验的地标观测 | RTAB-Map | 建图阶段保存数据库和二维导航栅格。巡检阶段加载已验收地图，提供 `map → odom` |
| 前后点云 | 分别裁剪、滤除机身与地面干扰，按用途降采样 | Nav2 局部代价地图和 Collision Monitor。停车支路保留经实测能发现低矮障碍的点云密度 |
| 前置相机图像、相机参数 | 去畸变 → `apriltag_ros` → 地标质量校验 | 标签 ID、相对位姿及观测质量 |
| 路线、拍摄窗口与目标配置 | 巡检任务管理器、Nav2 Waypoint Follower、Regulated Pure Pursuit | 规划、路径跟踪和行进中拍摄调度 |
| Nav2、Web 遥控与桩前对准的速度请求 | 运动仲裁 → Collision Monitor → 底盘桥接 → Unitree SDK2 | 由底盘桥接执行限速和指令超时处理，并调用 A2 `Move()` 或 `StopMove()` |

- TF 主链为 `map → odom → base_link → 各传感器坐标系`。RTAB-Map 和 DLIO 各自负责一段动态 TF。用宇树文档外参初始化双雷达静态 TF，并通过实机重叠点云检查轴向和对齐。若 DLIO 输出的是 IMU 或雷达位姿，先转换为机身位姿。
- ROS 2 点云类型为 `sensor_msgs/PointCloud2`，IMU 为 `sensor_msgs/Imu`。驱动话题名、QoS、点内时间字段名与单位、时钟来源和实际频率，在首轮录包后记录并固化。按所选 ROS 2 版本统一速度消息类型、坐标约定和超时语义。
- 建图时遥控采集往返路线、岔口和设备点。将 RTAB-Map 数据库、同坐标系的二维栅格、巡检点与标签表作为同一版本发布。巡检时从已知入口位姿初始化，确认全局定位有效后才允许自动运动。点位至少记录点位 ID、地图版本、目标位姿、照片路径、抓拍时间和实际位姿。
- 实现巡检时把堵路设为等待或暂停。检查 Nav2 行为树和恢复行为，避免狭窄区自动旋转、倒退或清空代价地图后误启动。只有障碍消失、传感器与定位正常且任务允许时才恢复。

## 3. AprilTag 辅助定位

**目的**是缩短长直重复区段的无校验里程，降低纵向漂移造成的错站。标牌可同时印业务二维码供人工扫码。每个定位标签使用唯一 ID，并登记位置、朝向、实际检测边长和服务方向。

- 先在入口、代表性长直段中部和易混淆设备前试点。用哑光标牌，朝向机器人接近方向。实测往返可见性，必要时在同一位置设置朝向不同、ID 不同的标记。
- 标定原装广角相机内参与畸变，测量相机到机身外参。以图像时间为准匹配相机参数和机器人位姿。根据边长、角度、距离、连续观测一致性和重投影误差筛除低质量观测。若视频时间不可靠，试点先停稳观测。
- 标记在建图时进入 RTAB-Map 地图数据库。实际版本支持时直接接入 AprilTag 检测接口，否则由适配节点发布 `landmark_detection`。将地标观测送入全局定位，连续里程计由 DLIO 维护。对关键点的异常大幅校正，暂停任务并复核。
- 标签尺寸与间距由原装补光、行走模糊、往返识别率、纵向漂移和到点容差共同确定。比较纯雷达与加入地标的到点误差，并遮挡一个标签复测。超过经验证的无校验距离时减速复读，仍无法确认位置就暂停。需要对齐图纸里程时，另外建立标签与测量坐标的对应关系。

## 4. Orin 部署与实机前置检查

| 核查项 | 处理 |
|---|---|
| 系统版本 | JetPack 6 / Ubuntu 22.04 用 Humble ARM64。若宇树已为该背包提供 JetPack 7 / Ubuntu 24.04 镜像，则用 Jazzy ARM64。JetPack 5 / Ubuntu 20.04 先保留出厂镜像，用 ARM64 Humble 容器验证 CPU 导航链路，并单独核对视频依赖。 |
| 雷达数据网 | 宇树文档列出的前后 JT128 地址为 `192.168.124.20`、`192.168.124.21`。从 Orin 验证实际 UDP 收包、驱动解码、IMU 输出和各路时钟。 |
| 底盘控制网 | 按整机文档核对 `192.168.123.0/24` 上的 SDK/DDS 通信。从 Orin 先验证状态订阅，再在有人监护条件下验证运动、停车、指令超时和控制权交接。SDK2 用 ARM64 库并验证目标系统上的链接与运行。 |
| 原装相机 | 确认背包能获得连续视频、实际分辨率与采集时间。必要时由 PC2 转发。先验证静止抓拍，再验证行走中 AprilTag 识别。 |
| 资源预算 | 先按 CPU 运行。用 `tegrastats` 观察 CPU、内存和温度，同时记录点云丢帧、里程计输出延迟和指令更新。RViz 在调试电脑上运行。 |

在 Orin 宿主机执行以下只读检查。路由输出用于确认所选网卡，链路以实收点云和 SDK 状态为准。

```bash
uname -m
tr -d '\0' < /proc/device-tree/model; echo
cat /etc/os-release
head -n 1 /etc/nv_tegra_release
free -h
ip -br addr
ip route get 192.168.124.20
ip route get 192.168.123.161
```

## 5. 开发顺序与验收

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| M0 接入和录包 | 核对 Orin 型号、JetPack、网段和驱动。录制前后点云、前雷达 IMU、相机及 TF，覆盖静止、直行、转弯。 | 两路点云可独立识别。点内时间可被 DLIO 解析，IMU 与点云时间对齐，点云在机身坐标系正确叠合。相机能取得可用图像。 |
| M1 里程计和地图 | 回放录包跑 DLIO，遥控完成代表性路段建图，保存数据库和栅格。测试同一入口多次重启后的定位。 | TF 连续且无重复发布，地图与实测路段相符。统计入口重定位成功率和用时、直廊纵向误差及返程误差。 |
| M2 导航和停车 | 打通经 Collision Monitor 的唯一自主速度指令通道。低速测试临时障碍、持续堵塞、点云掉线、定位异常和指令超时。 | 受测障碍触发正确减速或停车。用实际步态测从检测到停稳的距离，并按方向、摆腿范围和现场地面设置停车区。沟槽、落差及楼梯先纳入禁行区。保留独立人工急停。 |
| M3 地标和巡检 | 用同一路线对比有无地标，测试往返识别、漏读、遮挡和相似设备点。联调行进拍摄、停稳补拍和记录。 | 在约定窗口内完成拍摄，照片与设备点位对应。标签质量不达标或定位不确定时，任务按配置暂停。 |
| M4 全程运行 | 在实际功耗和散热条件下完成整趟路线，记录导航时延、资源占用、到点和故障恢复。 | 全程满足现场设定的误差、停车距离、任务成功率和资源余量，完成首期交付验收。 |

**开工任务从 M0 开始。** 目前待实测的数值包括巡检速度、到点容差、停车距离、标签尺寸和间距、重定位超时，以及 Orin 的负载余量。把这些数值和测试条件记录在验收表中，再固化到部署配置。

## 6. 任务编排与载荷扩展

定位、导航、载荷和桩前对准分别作为 ROS 2 模块。由 Orin 上的巡检任务管理器协调，统一使用任务 ID、地图版本和采集时间。载荷节点独立处理设备通信和重连，视频处理、磁盘写入或气体通信超时不能阻塞导航控制和停车。

| 模块 | 接口建议 | 职责 |
|---|---|---|
| 巡检任务管理器 | 路线配置、Nav2 动作、载荷动作与状态事件 | 管理拍摄窗口、任务进度、异常暂停、电量余量、返桩对准和任务记录 |
| 云台相机适配 | 瞄准与抓拍动作、云台角度和图像反馈 | 封装实机 SDK 或设备协议，报告实际角度、帧时间和失败原因 |
| 气体采集适配 | 带时间戳的读数、设备诊断与报警事件 | 封装实机协议，输出浓度、单位和有效性，断网时本地记录 |
| 桩前对准 | 对准动作、取消、桩相对位姿和对准结果 | 负责近场定位、低速对准和原厂交接 |
| Web 通信网关 | 任务命令、遥控会话、状态事件及媒体文件 | 将上位机请求映射为机载动作并回传结果 |

配置按路线登记 `segment_id`、方向和巡检目标。设备记录包含 `asset_id`、地图坐标或已示教云台预置位、允许拍摄区间、取景约束、补拍策略。数据记录包含 `mission_id`、地图版本、传感器时间、位姿和结果状态。支持取消、超时与有界重试，重启后从持久化检查点恢复进度并重新确认当前定位、设备与底盘状态。

### 6.1 行进中云台拍摄

1. **提前进入拍摄窗口。** 用路线段和沿路线进度确定触发，按任务路线方向筛选，防止返程或相邻支路误拍。窗口起点按云台转动、稳定和相机延迟实测设置。固定目标可先用现场示教预置位；若按地图三维坐标瞄准，则用采集时刻的机身位姿和标定后的 `base_link → 云台基座 → 云台轴 → 相机光学坐标系` 计算指向，并补偿行走中的机身转动。
2. **行进中抓拍并核验。** 在窗口内按实测可用速度拍摄，检查目标入框、清晰度和曝光，必要时连拍择优。记录目标 ID、路线方向、曝光时间或已校验的帧时间、机身位姿、云台反馈角度和质量结果。首期可人工验收图像质量，自动门限依据样本确定。
3. **按结果补拍。** 拍摄失败时可在窗口内减速重试。允许停车的点可停稳补拍。关键设备仍失败时标记任务异常，按点位策略暂停或留待人工复查。拍摄节点通过任务管理器请求速度约束，底盘仍由统一运动链路控制。

### 6.2 气体与其他传感器

- 气体沿线持续采样，保存原始读数、单位、有效性、采样时间及对应位姿。按现场需求配置定点停留测量。传感器预热、校准状态、采样流量与通信故障作为诊断，失效读数标为无效并触发任务降级。
- 在实际安装位置测气体传感器响应时间。有采样管时计入输送延迟。气体异常记录应包含位置不确定度，结合车速、响应时间和气流解释，避免把报警时机器人所在位置直接标成泄漏源。
- 气体门限、校准流程及报警后停车、撤离或等待指令的行为，由现场规程确定。涉及爆炸危险区域时，在实地运行和充电前核对整机、载荷与充电设备适用于现场分区。机器人气体采集与现场既有保护和联锁分别管理。
- 后续载荷按相同方式提供数据、诊断或异步动作。现场核实供电、带宽、安装重量和外廓，复核散热、步态稳定性、雷达遮挡、停车区和充电桩净空。

## 7. 原厂充电座定位与对准

任务结束、操作员发出返桩命令或低电量策略触发时，Orin 从已登记的原厂充电座中选择目标。每个 `dock_id` 关联地图版本、桩前预对准位姿、目标对准位姿、进桩方向和允许的搜索范围。

| 阶段 | Orin 负责的工作 |
|---|---|
| 导航到桩前 | Nav2 根据地图导航至预对准位姿。返桩电量阈值依据实测能耗、剩余距离、对准重试和余量设置。 |
| 近场定位 | 在桩前识别指定充电座，估计机器人相对充电座的位姿。若原厂接口提供可用的近场位姿则直接接入。否则优先验证用原装前置相机观测专用 AprilTag 的可行性，并标定标签到目标对准位姿的固定变换。 |
| 低速对准与交接 | 使用连续 `odom` 和新鲜的桩相对位姿闭环对准。达到原厂允许的位置和角度范围、机器人停稳后，报告 `ALIGNMENT_COMPLETE` 并按原厂流程交接。 |
| 异常退出 | 遮挡、目标不一致、定位过期、人员闯入或超时，先停车。允许的重试次数和可退回的位姿由现场验证。无法恢复则报告 `ALIGNMENT_FAILED` 并等待处置。 |

对准完成是本项目的终态。充电触点、充电启动、充电状态确认和离桩流程由原厂系统负责。上位机显示“对准完成／已交接”，只有原厂系统提供并接入独立状态时才可另外展示其状态。

自研对准和 Nav2 使用同一个运动仲裁器及防撞链路。交接时先撤销自研运动授权。若原厂流程还会驱动底盘，需要通过原厂状态或人工确认明确控制权归属，交接后保持导航和 Web 遥控禁用，直至底盘明确释放且任务重新授权。M0 核对原厂对准方向、位置与角度容差、交接触发方式和控制权释放条件。现场检查桩体与停车区的相互影响，保持人员及其他障碍监控。

## 8. Web 上位机通信

首期假定现有 Web 平台有可对接的业务后端。Orin 新增 `robot_gateway`，在机载侧把 Web 请求映射成白名单内的 ROS 2 动作与状态。推荐 Orin 主动通过 **WSS** 连接上位机后端，网页沿用现有后端接口。照片、地图栅格等文件通过 **HTTPS** 单独上传或下载。车内 DDS 留在机器人网络。

| 通道 | Web 平台与 Orin 交换的内容 |
|---|---|
| 任务命令与反馈 | 启动、暂停、继续、取消、返桩。启动命令带 `route_id`、`map_version`，结果关联 `request_id` 和 `mission_id`，区分已接收、已拒绝、执行中与最终结果。 |
| 人工遥控 | 申请和释放控制权，按住使能时发送限速后的速度请求。每条命令带会话、顺序号和有效期。Orin 只接受当前会话的新鲜指令，经运动仲裁及 Collision Monitor 后转交底盘。 |
| 实时展示 | 地图版本、机器人地图位姿及定位质量、当前路线段、任务进度、模式、电量、避障或堵塞事件、气体读数、云台拍摄结果和桩前对准状态。位姿消息携带时间戳与坐标系。 |
| 文件和视频 | 巡检照片按 `mission_id`、`asset_id` 与拍摄时间关联。本地保存后异步传输。首期优先做缩略图和原图查看。若现有平台需要直播，沿用其媒体通道或另配媒体链路，带宽不足时优先保证控制与告警。 |

- **控制权互斥。** 自动巡检、Web 遥控、桩前对准和原厂接管各自有明确的授权状态。切换前撤销旧授权并停稳。Web 停车命令属于远程软件停车，现场独立急停仍优先。
- **断网和重连。** 人工遥控断网、松开使能或控制租约超时立即失效，由 Orin 在本地停车。首期自主任务断网默认暂停在经现场确认的安全位置，保留进度和采集记录。后续仅对已验收路线开放离线巡检，仍由机载安全逻辑约束。重连先同步完整状态再续传事件、照片，历史运动命令一律过期。任务命令按 `request_id` 去重，避免重发启动第二个任务。
- **访问边界。** 机器人连接使用设备身份，后端区分查看与操控权限。控制会话同一时刻只有一个持有者。接口版本、消息序号、任务时间戳和故障码纳入联调记录。日志保留操作人、命令、确认结果和模式切换。
- **联调先用模拟端。** Orin 与现有平台先对齐认证方式、接口命名、消息格式和地图坐标。先用模拟任务、气体数据和照片跑通界面，再接真机测断网停车、控制权切换、重连去重和弱网上传。

## 9. 扩展开发与验收

| 阶段 | 交付与验收 |
|---|---|
| 与 M0 并行做接口验证 | 取得云台和气体设备接口说明，台架验证控制、数据和时间戳。尽早验证原厂桩的对准容差、交接条件与控制权释放。并行核对 Web 平台后端与认证接口。 |
| 在 M2 后联调载荷 | 用现场阀门验证移动拍摄命中率、可读性、错站率和补拍次数。验证气体样本定位关联、采集掉线、告警及数据落盘。 |
| 在 M4 前验收桩前对准 | 验证终点返桩、低电量提前返桩、桩前有人、目标遮挡、取消和交接。统计对准位置与角度误差、完成率、耗时与重试次数。 |
| 在 M4 前验收 Web 联动 | 验证任务启停、遥控授权、断网停车、重连去重和记录补传。弱网下验证状态及时更新，媒体上传不阻塞控制。 |
| 全程复测 | 使用实际载荷跑完整路线，记录拍摄质量、气体数据完整性、到点、桩前对准和 Web 操控结果，并复测避障停车距离、Orin 资源与能耗余量。 |
