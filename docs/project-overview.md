# A2 地下管廊离线巡检项目说明

项目以 A2-PRO 机器狗和机载计算平台为基础，目标是在地下管廊沿预定路线自主巡检，在点位采集照片和气体数据，将结果与位置关联，在异常或低电时执行处置和返桩流程。巡检期间可以没有外部网络，任务、地图、路线、参数和记录均由机载系统管理，维护联网后再同步成果。

当前已完成新 A2 原装前雷达和 IMU 的断网录包、整圈离线建图及闭环复测。自主巡航、控制权交接和实际停车仍待实机验证。软件包实现与现场验收进度见[开发进度说明](implementation-status.md)。

## 运行与维护

- **运行期间**由机载系统使用本地程序和数据。外网不可用是预期工况。机内传感器、DDS 和底盘控制链路故障按运行故障处置，停车与撤权链路独立于数据库写入和媒体处理。
- **维护期间**由开发机通过维护网络或离线介质传入固定版本的程序与配置，采集原始数据并回传日志。公共 GitHub 仓库用于代码管理和维护期传递。
- **设备范围**以原装雷达、IMU 和摄像头为基础。本轮建图使用前雷达及其配套 IMU，新增云台、气体等巡检载荷按安装进度接入。

## 软件架构

项目采用 ROS 2 单仓库工作区，业务逻辑与设备、ROS 通信分开。任务核心管理准入、任务状态和点位进度，平台层封装原厂接口，导航与安全模块按各自职责处理路线和运动许可。

| 层 | 主要职责 | 对应模块 |
| --- | --- | --- |
| 设备与模型 | 接入原装传感器和底盘状态，统一机身与传感器坐标 | `a2_platform`、`a2_description` |
| 定位与建图 | 校核点云和 IMU 时间，生成去畸变点云与连续里程计，建立和使用地图 | `a2_localization`，组合 DLIO、RTAB-Map 等组件 |
| 导航与安全 | 执行固定路线，检查定位和障碍，按授权仲裁、限速和停车 | `a2_navigation`、`a2_safety`、`a2_platform` |
| 巡检业务与存储 | 编排任务和点位，调度载荷，保存任务检查点、事件及成果 | `a2_mission`、`a2_payloads`、`a2_storage` |
| 集成与维护 | 定义公共接口、组合启动、维护会话、结果同步和测试环境 | `a2_interfaces`、`a2_bringup`、`a2_gateway`、`a2_test_support` |

设计中的运动请求依次通过安全仲裁、防撞和平台桥接，再进入 Unitree SDK2。启用实机运动须核实原厂控制权、取得本地授权，并验证实际停稳和接收端失联停车。模块接口、TF 和启动约束见[软件架构](architecture.md)及[设计方案 v0.5](design/A2-PRO_Utility_Tunnel_Navigation_v0.5.md)。

| 启动模式 | 用途与可用范围 |
| --- | --- |
| `mock` | 当前默认启动组合，用合成状态验证任务和 SQLite 恢复。 |
| `replay` | 已有独立建图回放工具，完整 profile 待集成。回放输入限于经选择的传感器、状态与 TF。 |
| `robot_readonly` | 用于实机状态和原装传感器核查。已具备只读节点和现场采集工具，完整 profile 待集成。 |
| `robot_motion` | 受控实机运动组合，待实现和验收。 |

## 开发与实机验证流程

1. 在本机开发和评审源码，通过仓库检查、单元测试、模拟演示或录包回放复现问题。本机验证环境以 Ubuntu 24.04、ROS 2 Jazzy、x86_64 为基线。
2. 在公共 GitHub 仓库以固定提交管理源码。维护时可在 A2 获取指定提交，或由本机打包成 ZIP、Git bundle 后离线传入。
3. 在 A2 候选目录核对系统、CPU 架构、驱动、ROS 2 与 SDK 版本，完成相应平台构建、设备核查及本轮受控验证。候选程序、配置、地图和测试结果关联同一版本。
4. 把录包与测试证据带回本机分析。通过相应阶段验收的版本进入下一轮测试。实机运行加载机载安装的程序、依赖与配置。

## 项目目录

| 目录 | 内容 |
| --- | --- |
| `docs/` | 设计、架构、现场流程、开发进度和验收说明 |
| `src/` | 自研包与[包计划](../src/package-plan.json) |
| `config/examples/`、`deploy/templates/` | 配置示例和发布清单模板 |
| `scripts/`、`tests/` | 采集与检查工具、自动测试、回放和实机报告模板 |
| `docker/`、`third_party/` | 开发容器定义、候选依赖与正式依赖清单 |
| `artifacts/`、`data/` | 本机受控的录包、地图、日志与试验产物，由 Git 忽略 |

源码仓库使用公共可见性，保存代码、通用文档、示例和经审查的合成夹具。现场地图、录包、标定、登录凭据和实机配置存放在受控位置。[仓库约定](github-setup.md)

## 阶段与验收

项目按 M0 原装接入与失效边界、M1 地图与定位原型、M2 受控导航与停车、M3 载荷与离线业务、M4 全程验收推进。采集和离线原型可先开展，实机自主运动以对应阶段的控制权、停车、定位与故障试验为准。[设计方案与验收条件](design/A2-PRO_Utility_Tunnel_Navigation_v0.5.md) · [开发进度说明](implementation-status.md)
