# A2 首次受控运动与停车验证

状态为准备中。人工建图由现场操作员使用原厂遥控，采集工具只读。可以在同一开发阶段准备停车验证，现场执行时将人工建图和自研控制试验安排在各自的操作窗口，明确每个窗口的控制权。机器人运行期间可以没有外部网络，机内传感器、SDK/DDS 链路和独立人工停车手段仍按本轮工况核查。[录包指南](mapping-capture.md) · [设计方案 §5.4 与 M0/M2](design/A2-PRO_Utility_Tunnel_Navigation_v0.5.md)

当前 `a2_platform` 提供只读节点和模拟状态源。原厂 `SportModeState` 的接收时序和原始 `mode` 可用于接口核查，机身速度坐标、原厂控制权、电量与独立停稳反馈仍需确认。历史只读观测发现了运动和租约接口的端点，当前固件的指令有效期、控制权释放和接收端失联行为须以厂商确认和实机证据为准。`a2_safety` 与完整 `robot_motion` 启动组合仍待实现，以下软件运动用例须在对应候选实现后执行。[平台只读实现](platform-readonly.md) · [SDK2 字段依据](unitree-readonly.md) · [测试阶梯](development.md)

## 现场先确认的边界

由现场负责人、原厂接口方和测试人员在对应实机试验开始前填写。将台架、原厂受限操作和自研运动各自的适用边界写入当次记录。所用速度、时间和距离从该记录读取，模拟配置值仅用于软件回归。将试验阈值与实测结果分开记录。

| 冻结项目 | 本轮确认值或证据 |
| --- | --- |
| 机器人型号、固件、目标 ARM64/ROS、SDK 版本、程序和配置摘要 | 待填写 |
| SDK 网卡与域、状态话题与字段、原厂控制权确认来源及变更信号 | 待填写 |
| 受测地面、方向、步态、载荷、外廓、允许速度和单次动作范围 | 待填写 |
| 停车边界，包括检测或故障触发至停稳的最大时间、距离和允许外廓 | 待填写 |
| 停稳的测量依据，包括可用速度字段、独立观测、保持时间和测量误差 | 待填写 |
| 命令最大年龄、授权有效期、关键输入过期门限、桥接循环时限 | 待填写 |
| 接收端失联触发条件、计时起点、可用反馈及验证方法 | 待填写 |
| 独立人工停车方式、负责操作的人、作用范围、复位和回收方式 | 待填写 |
| 试验区边界、人员位置、监督人、记录人、重复次数和终止条件 | 待填写 |

## 执行顺序

1. **本机预检。** 复核模拟停稳、过期输入和重启后的权限行为。准备带版本和受测工况的记录，检查用于停稳测量的标尺、视频和日志的时钟对齐方法。
2. **M0 静止核对。** 在维护窗口核对版本、机内状态和原厂控制权。用只读记录确认哪些数据能够判断状态变化和停止，哪些必须由独立观测补足。按原厂流程确认人工停车、复位和回收方式，由指定监护人控制操作窗口。
3. **M0 验证接收端失联。** 由现场和原厂选定台架或批准的最小动作。先验证人工停车，再分别测量 SDK 指令中止、发送方消失和机内通信失联时仍然存活的底盘停止机制。记录其停止原因和实际停稳。无法证明接收端有界停稳时，继续核查原厂接口或台架，保留人工建图方式。
4. **M2 验证唯一运动链路。** 用已核实的控制权反馈和现场新授权开始受限测试。先做软件停车与取消，再依次验证命令过期、定位失效、传感器断流、进程退出及控制权变化。各用例完成后复核实际停稳和授权状态，再按新的试验条件执行下一项。

## 停车和控制权用例

| 用例 / 阶段 | 条件和观测 | 通过所需证据 |
| --- | --- | --- |
| `M0-STOP-01` 独立人工停车 | 在原厂批准工况中操作独立停车，确认作用范围与复位过程。 | 独立录像或量测记录触发至实际停稳的时间、距离和保持情况。复位后维持停稳，后续动作需要新授权。 |
| `M0-STOP-02` 底盘接收端失联 | 依批准方法让发令侧停止更新、控制链路失联或 Orin 不可达，分别记录每种工况。 | 底盘在冻结边界内实际停稳。证据同时表明触发后发送侧无法继续发有效运动或停车请求，并说明哪个存活机制执行停车。 |
| `M0-OWN-01` 原厂控制权 | 核实原厂占有、释放及未知三种状态的证据来源。 | 原厂占有或状态未知时，自研授权为 `NONE`。在原厂释放后仍保持无授权，直到完成新一轮检查与授权。 |
| `M2-STOP-01` 软件停车、暂停和取消 | 经唯一运动链路发起已批准动作，分别验证停止、暂停和取消的撤权路径。 | 记录撤权、停车请求、响应和实际停稳。确认停稳后才能报告取消完成。未能确认时锁存 `STOP_UNCONFIRMED`。 |
| `M2-AGE-01` 命令与授权过期 | 在批准的测试方式下检查停止续期、陈旧、重复、乱序与旧授权代号。 | 使用机载单调时钟区分最后一条有效指令、过期判定和实际停稳。旧指令和重连消息不能刷新授权或引起再次动作。 |
| `M2-LOC-01` 定位失效 | 在受控环境中验证定位失锁、状态过期、重定位结果不明确。 | 撤销运动授权并在冻结边界内停稳。定位状态恢复后保持故障锁存，现场核对并重新授权后才可继续。 |
| `M2-SENSOR-01` 障碍和关键输入失效 | 分别验证障碍触发、前后向覆盖、关键点云/TF 过期及防撞输出失效，覆盖本轮允许的方向。 | 防撞或桥接记录触发原因。独立量测证实停稳距离和外廓符合冻结边界。 |
| `M2-EXIT-01` 桥接退出与重启 | 按 M0 核实的方法分别验证正常退出、异常退出、Orin 不可达和 SDK 链路断开。 | 正常退出有撤权和实际停稳记录。发送方消失或链路断开时有接收端和独立观测的实际停稳证据。重启后的旧授权、缓存和请求都不能驱动底盘。 |
| `M2-OWN-01` 控制权交接 | 观察原厂接管、控制权未知和恢复释放，核对旧来源失效。 | 执行撤权、停稳验证和新授权的顺序。原厂占有或未知时由约定的原厂停车方式负责，软件不争抢控制权。 |

每次试验记录测试触发、最后一条有效指令、软件撤权或失效判定、接收端可用状态、实际停稳和停稳后的观察时间。能在同一进程或时钟域比较时使用单调时间，并记录 `boot_id`。对视频或另一计算机的记录，用同一可观测事件对齐并登记误差。SDK 请求返回值、界面状态和速度估计作为软件证据，现场停稳由已核实的底盘反馈结合独立录像或量测确认。遇到超出已冻结边界、停稳证据缺失或控制权不明时，按现场约定由监护人处置并保留失败记录。逐项归档为通过、失败、未执行或证据不足。[实机报告模板](../tests/hil/report-template.md)

## 本机回归记录

本轮运行了现有任务控制器和模拟适配的 38 项用例，以及独立编译的 14 项平台状态用例，全部通过。覆盖停稳未确认时保持故障、授权过期和重启后旧凭据无效、定位失败锁存，以及缺失、陈旧、重复或乱序状态的处理。上述回归使用合成输入，实机运动与停车各项当前为未执行。[任务模拟说明](mock-mission.md) · [平台状态测试](platform-readonly.md)

在项目根目录复现任务回归。

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src/a2_storage:src/a2_mission \
  python3 -m unittest discover -s src/a2_mission/test -v
```
