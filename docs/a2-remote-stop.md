# PC2 独立遥控停车

PC2 上的 `a2-remote-stop.service` 单独监听原厂遥控器。现场指定按钮的位一旦出现在 `rt/lf/lowstate` 的 `wireless_remote` 中，守护进程请求 A2 sport 的 `StopMove`，锁住自主启动并请求 systemd 终止 `a2-autonomy.service`。松开按键后锁存持续有效。程序沿用当前运动模式，实际站定由机身反馈确认。该按钮依赖遥控数据传到 PC2、PC2 正常运行并能向底盘发令。现场人员只在碰撞危险迫近时操作独立急停，切断电机输出。本项目的 A 键制动时间、行程及自主进程退出情况均从真实 A 键和同期日志测量。[实机控制与停车验证](a2-first-motion-test.md)

## 静止辨认按钮

在 PC2 使用已安装 A2 专用 SDK 的 Python、实际机内网卡和 DDS 域。机器人站稳、自主程序退出后，选取经现场确认不会切换步态或触发其他原厂动作的按钮。以下的环境变量由现场填写。

```bash
"$A2_STOP_PYTHON" /opt/a2/scripts/a2_remote_stop.py observe \
  --interface "$A2_STOP_INTERFACE" --domain "${A2_STOP_DOMAIN:-0}"
```

记录松开、单独按住、再次松开三个状态的按键位，重复几次。把稳定出现且只含一位的按键掩码写入配置。2026-11-22 在本台 A2 上连续两次读到 A 键按下为 `0x0100`、松开为 `0x0000`。观测程序只读取遥控信号。

本台 PC2 静止实测中，`LowState.tick` 以约 20 Hz 推进。高、低频运动状态的 `SportModeState.stamp` 均为零，低频同一 DDS 发布端的 40 帧源时间逐帧递增。仅在设备时间明确为零时，守护使用 DDS 源时间检查机身反馈的连续性，同时独立检查低层 IMU 计数、姿态、速度与位移。遥控无线断开后机身是否继续发布缓存值仍需单独验证。

## 配置两项 PC2 系统服务

1. 将同一版本的 `scripts/a2_remote_stop.py` 与 `scripts/a2_remote_stop_sdk.py` 安装到 PC2 的 `/opt/a2/scripts/`，把两个服务模板装入 `/etc/systemd/system/`。部署树、服务文件及现场入口由管理员管理，普通自主程序账号仅有读取、执行权限。[停车守护模板](../deploy/templates/a2-remote-stop.service) · [自主程序模板](../deploy/templates/a2-autonomy.service)
2. 在仅管理员可写的 `/etc/a2/remote-stop.env` 中填写 `A2_STOP_PYTHON`（含原厂 SDK 的 Python 解释器绝对路径）、`A2_STOP_INTERFACE`（网卡）、`A2_STOP_DOMAIN`（默认 0）和 `A2_STOP_BUTTON_MASK`（实测的十六进制单位掩码）。配置文件使用 systemd 的 `变量=值` 格式。SDK 动态库及模块路径需在服务环境中可用。
3. 守护使用系统服务权限请求 systemd 停止固定的自主服务。自主服务使用现场配置的非特权账户 `a2-autonomy`。提供可执行文件 `/etc/a2/autonomy-start`，让它以 `exec` 方式启动现场选定的前台自主程序。任务调度、导航执行和唯一底盘发送进程都要在该服务控制组内。ODIN1 定位、只读服务和原厂运控独立运行。当前直接从终端运行的限速及半米试验脚本属于独立试验，不受此服务终止机制管理。
4. 在 PC2 的维护窗口重新加载服务文件。现场确认机身静止、自主服务已退出后，为停车守护启用开机自启并启动它。首次联调使用不接触底盘的模拟自主进程，核对进程组归属和停机行为。自主服务仍由现场显式启动。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now a2-remote-stop.service
systemctl is-enabled a2-remote-stop.service
systemctl status a2-remote-stop.service a2-autonomy.service
journalctl -u a2-remote-stop.service -u a2-autonomy.service -b
```

**静止验证开机自启。** 重启前记下 `/proc/sys/kernel/random/boot_id` 和守护锁存状态。保持遥控按键、摇杆松开，在维护窗口重启一次 PC2。重新登录后先读启动 ID，再查 `systemctl show a2-remote-stop.service -p UnitFileState -p ActiveState -p StatusText -p NRestarts` 和本次启动日志。验收时启动 ID 应已更换，守护应自行进入 `enabled`、`active`，自主服务应保持 `inactive`。若重启前已锁存，还应读到恢复锁存的日志，且没有 `/run/a2-remote-stop/ready`。全程保留锁存，记录停车回执与机身反馈各自的结果。

守护允许自主启动时提供 `/run/a2-remote-stop/ready`。锁存保存在 `/var/lib/a2-remote-stop/latched`，系统重启后继续阻止自主启动。订阅启动后 3 秒仍无计数推进的遥控帧、运行中连续 0.35 秒缺少新鲜遥控帧或守护程序停止也会锁存。守护异常退出后重新启动时，程序根据持久记录恢复锁存。systemd 看门狗监视主循环心跳，超时为 5 秒。

按键触发时，守护并行发起底盘停车和受管自主服务停机。它以 `systemctl stop --no-block` 提交停机作业，若自主程序仍在运行，立即强制终止整个专用控制组。确认发送进程退出后再请求一次底盘停车，覆盖已在途的速度指令。模板中的 2 秒是常规停止自主服务时允许进程自行退出的宽限。实际制动时间须现场测量。

## 发令进程意外退出

`a2-autonomy.service` 的 `ExecStopPost` 由 systemd 在发令进程外执行。钩子核对本次启动、单元离开 `active` 和主进程退出的单调时间。单元先进入停机、随后主进程正常退出时保持布防。发令进程强杀、先于单元停机自行退出或退出状态无法核实，则登记故障并阻止服务再次启动。独立守护读取故障后沿用停车锁存、清退和新鲜停稳反馈流程。守护脚本与单元模板需配套更新。[停车守护](../scripts/a2_remote_stop.py) · [发令服务模板](../deploy/templates/a2-autonomy.service)

开发机验证使用本地模拟发令子进程、合成底盘和模拟 systemd 输出。子进程收到 `SIGKILL` 后，模拟底盘保持最后一次运动输入，直到守护调用停车。测试在守护仍运行时核对停车请求、停稳、准入撤销和持久锁存。[开发机模拟用例](../scripts/test/test_a2_remote_stop.py)

2026-11-26，保持正式停车锁存，在 PC2 上部署守护和退出挂钩增补。使用 PC2 的 systemd 249 运行两项隔离单元，模拟底盘只使用本地文件验证运动与停车，正式发令进程保持停止。从发起 `SIGKILL` 到首个模拟停车调用约 90 毫秒，到确认模拟停稳约 854 毫秒。守护写入隔离锁存，systemd 拒绝启动模拟发令服务。正常停止模拟发令服务时，守护保持就绪。清理临时单元后，正式守护仍在运行，正式锁存的文件内容和 inode 保持一致。[部署记录](implementation-status.md#发令进程异常退出的隔离验收)

实机第 4 项中，发令主进程异常退出后，独立守护约 115 毫秒发停并自动锁存。机身与 IMU 的独立停稳确认用时 1.289 秒，现场最大对地位移约 0.020 米。按后续调整的 2.00 秒和 0.10 米验收上限复算通过。[实机验证记录](implementation-status.md#发令进程异常退出的实机验证)

## 分模式确认停稳

2026-11-22，PC2 已部署适配器 `9fdd9197f2c8`。下趴实机静态检查中，守护从判定参考回执起 0.752 秒后确认停稳。随后观察同一守护实例 70.52 秒，锁存持续有效，日志中新增停车调用和错误均为零。站立分支另有历史实机数据的离线回放验证。[现场验收记录](implementation-status.md#pc2-独立遥控停车)

| 原厂运动模式 | 守护使用的反馈 |
| --- | --- |
| 正常站立 `DEFAULT_MODE=3` | 原厂三维合速度须 ≤ 0.016 m/s，偏航角速度绝对值须 ≤ 0.05 rad/s。继续使用低层 IMU 的有效四元数、倾角与角速度，以及窗口内的三维位置变化。 |
| 下趴 `STAND_DOWN=1` | 原厂三轴速度在这个姿态下有重复报告非零值的现场记录。守护改用低层 IMU 和 12 个腿关节的实测反馈。各关节转速绝对值须 ≤ 0.10 rad/s，每个关节在窗口内的角度最大值与最小值之差须 ≤ 0.001 rad。把重力按四元数投影至机身三轴后，与实测加速度的矢量差须 ≤ 0.50 m/s²。以上三项为下趴离线候选门限。 |

两种姿态均要求步态、错误码为零，IMU 倾角 ≤ 12°，三轴角速度的各轴绝对值 ≤ 0.05 rad/s。机身位置包围盒对角线超过 0.015 m 即否决该窗口。下趴时只用位置排除可见位移，停稳仍需 IMU 和关节两组有效反馈。这两组传感器能观测姿态变化、加速度和关节活动，对整机被匀速搬运时的对地速度没有独立观测能力。

自主服务退出并取得后续停车回执后，两路反馈须在同一姿态下连续覆盖至少 0.50 s。姿态切换、故障、陈旧或缺帧会中断确认。下趴时额外核对低层 DDS 写者、源时间和设备计数。即使计数推进，IMU 或整组关节读数连续 0.20 s 没有更新，也不能确认停稳。`stationary_feedback` 仅记录停车反馈；解除锁存仍需独立的人工复位。

## 验证与复位

开发机的模拟输入可以验证按键识别、锁存及异常处理。ROS 2 模拟目标只覆盖任务链路。2026-11-22，PC2 实测了静止和迈步后的 A 键停车。迈步后按 A 的一轮中，A 键守护首先发停，systemd 在独立监督发现速度越界前已向真实发令进程发出终止信号。独立监督随后补发停车。后续测量按下表分别核对停车请求、进程退出和机身站定。[实机时间线与距离](a2-stop-test-results-20261122.md#迈步后由-a-键首先发停)

| 证据 | 如何判断 |
| --- | --- |
| 停车请求 | 记录按键接收、`StopMove` 请求及返回码，分别计算输入到发令和发令到回执的时差。 |
| 自主退出 | 核对自主服务终态、控制组中发送进程全部退出，以及锁存后不能再次启动。 |
| 机身站定 | 核对连续新鲜的机身速度、角速度和位置，并由现场测量从按键到持续站定的时间和距离。无回执、状态断流或数据不足时保留为未确认。 |

### 驾驶舱复位

维护隧道已连接、两路机载状态均确认守护正在运行且停车已锁存时，驾驶舱顶部显示可用的「复位停车锁存」按钮。操作员现场确认 A2 已停稳、触发原因已排除、原厂手柄 A 键已松开且摇杆回中后，勾选确认并提交一次。

PC2 收到请求后独立确认发令服务与其进程组已退出，并使用只读反馈复核手柄回中和机身停稳。复位期间，机载标志阻止自主单元启动。PC2 确认守护重新布防后才提交复位，异常退出则优先恢复停车锁存。驾驶舱收到新鲜的「停车未锁存」遥测后才提示成功。若请求断线或超时，驾驶舱继续观察当前状态。复位完成后的运动许可仍由机载入口单独签发。[驾驶舱维护通道](a2-operator-console.md#实机运动接入) · [机载复位入口](../scripts/operate_a2_stop_reset.py)

### PC2 现场复位

确认机身已站稳、自主服务已退出并排除触发原因后，松开按钮，由现场管理员依次停止守护、复位和重新启动守护。复位程序必须取得守护互斥锁，并确认自主单元及其后代进程都已退出。

```bash
sudo systemctl stop a2-remote-stop.service
sudo "$A2_STOP_PYTHON" /opt/a2/scripts/a2_remote_stop.py reset
sudo systemctl start a2-remote-stop.service
```

检查 `/run/a2-remote-stop/ready` 和守护日志后再准备新任务。复位只解除锁存，自主任务需重新授权并单独启动。
